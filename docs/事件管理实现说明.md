 # 事件管理实现说明

事件管理入口为“工单管理 → 事件管理”，页面路径 `/incidents`，接口前缀 `/api/v1/incidents`。事件使用数据库 `ticket` 主单，类型为 `INCIDENT`，其余事件信息通过接管任务、意见、责任区间、协作线程及审计记录关联保存。

## 已实现

- 事件列表、组合检索、个人页签、分页、详情、保存/修改/提交草稿、正式创建及服务台代录。
- 首次分配、重新分配、接管、申请退回与审批、撤回、处理意见、转交责任。
- 多人转发、独立协作线程、首次阅读记录、协作回复、撤回及访问权撤销。
- 挂起/恢复、完整解决方案、确认关闭、退回处理、无效关闭、归档、申请重开、授权重开。
- 意见追加更正及原记录关联；事件和协作附件上传、意见附件关联、受权限保护的下载。
- 完整动作时间线、历史人员/部门快照、责任区间、处理周期、累计计时耗时及分页查询。
- 站内通知、未读/已读、工作台待办统计、人工催办及自动超时提醒。
- 事务、事件版本检查、幂等请求、接管任务唯一约束、当前责任区间唯一约束。

所有事件写入均经过服务端身份、事件关系、权限及状态校验。分派额外校验当前有效 `SEAT` 角色和数据库中的实际分派权限，不使用管理员的通用权限直通。历史处理人及协作接收人的可见关系不会自动授予当前处理权。

通知通过事务中的 outbox 入队，由独立事务投递到站内消息表。投递失败保留次数和失败状态并自动重试，不撤销已提交的事件动作。具有审计权限的用户可以通过 `GET /incidents/notification-deliveries` 在其数据范围内查询投递记录。

## 草案冲突的实现基线

- 分配、转交只产生一个待接管人；人员角色可多选作为检索条件，转发接收人可多选。
- 草稿仅创建人可见，删除采用软删除，隐藏主单并保留审计；正式事件无物理删除接口。
- 归档后允许服务台或保留的当前责任人再次转发供查阅；禁止提交意见、协作回复或附件，归档前开放线程标记结束。
- 有效历史处理人重开时恢复处理，指定新人员必须经服务台分派并重新接管。
- 解决结果退回时若原处理人停用或部门不再有效，保留旧方案，启动新周期并回到待分配，通知服务台处理，避免事件滞留。
- 普通意见不可覆盖或删除；补充更正引用本人原意见，解决方案需要通过退回处理后重新解决。

## 数据迁移和策略

新增 Flyway 迁移 `V5__incident_management.sql`，创建事件表及权限、分类和配置。现有工单接口没有持久化历史事件，因此没有猜测映射旧 `PENDING`、`ACCEPTED` 状态。

迁移给内置角色配置对应事件权限，但不会给管理员自动增加 `SEAT` 角色。管理员需要组织正常授权后才能分派。

以下配置保存在 `sys_config`，为可调整的开发默认值，不表示组织已经批准的 SLA：

| 配置 | 默认值 |
| --- | --- |
| `incident.takeover.minutes` | 120 分钟 |
| `incident.sla.P1` | 响应 15 分钟，解决 240 分钟 |
| `incident.sla.P2` | 响应 30 分钟，解决 480 分钟 |
| `incident.sla.P3` | 响应 120 分钟，解决 1440 分钟 |
| `incident.sla.P4` | 响应 240 分钟，解决 2880 分钟 |
| `incident.suspend.pause` | 等待必要外部条件时暂停解决时钟 |
| `incident.attachment.max-mb` | 单文件 20MB |
| `incident.attachment.max-count` | 单次 10 个 |
| `incident.attachment.quota-mb` | 单事件 200MB |
| `incident.attachment.extensions` | PDF、文本、图片、Office 文档、日志、ZIP |

分配及转交不会重置事件 SLA；优先级调整必须有权限和原因，并重新计算响应/解决期限，记录原期限和新期限。解决后的确认等待时间不计入重新处理周期。挂起的暂停策略在挂起时保存，后续修改全局配置不会改变该次挂起的计算方式。

定时任务间隔可以通过配置覆盖：

```yaml
itsm:
  incident:
    notification-interval-ms: 5000
    reminder-interval-ms: 60000
```

附件复用项目 `ObjectStorage`。上传事务失败会清理此次已写入的文件；下载通过事件接口校验资料和线程权限，不向客户端暴露存储键。

## 验证

前端：

```sh
cd itsm-ui
npm install
./node_modules/.bin/vue-tsc --noEmit
npm run build
```

后端：

```sh
cd itsm-server
mvn test
```

真实 PostgreSQL 集成测试需要指定测试数据库。测试为每次运行创建独立 schema，结束后删除该 schema：

```sh
export ITS_INCIDENT_TEST_DB_URL='jdbc:postgresql://localhost:55432/incident_test'
export ITS_INCIDENT_TEST_DB_USER='incident_test'
export ITS_INCIDENT_TEST_DB_PASSWORD='incident_test'
mvn package
```

未设置测试数据库时，只运行无需数据库的事件策略测试，PostgreSQL 集成用例明确跳过。集成用例覆盖生命周期、权限绕过、角色停用、协作隔离、撤回、并发、幂等、长 ID、挂起计时、通知失败重试、附件下载权限、意见更正和优先级调整。

另外在临时数据库中验证了应用启动、真实登录及 HTTP 创建 → 分配 → 接管 → 转发/回复 → 处理意见 → 解决 → 关闭 → 归档流程，验证管理员分派被拒绝、归档写入被拒绝及子资源分页。

10 万事件、100 并发的建议负载指标尚未压测，需结合约定的部署环境验收。邮件、短信、自动分派、外部接收人、复杂审批和自动归档保持需求说明书中的后续范围。
